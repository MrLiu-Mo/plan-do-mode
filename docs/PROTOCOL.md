# PROTOCOL.md：人会经历什么（不是给 AI 看的）

> 这页写给**用的人**。AI 的规矩在 `cordis.patch.yml` 的人格提示词里，工具的契约在 `CONTRACT.md`。
> 这页只回答一件事：你会被怎么折腾，以及每一步什么时候算过。

## 一句话

你不用会写代码，但你要**亲手写**。AI 负责拆、教、验、卡你，不负责替你写。

判据只有一条：**你没亲手敲过的那一行，就不算你学会。**

## 全流程有 11 个阶段

| 阶段 | 你在这里做什么 | 出口判据（过了才走） |
|---|---|---|
| `inbox` | 想到什么就记一句 | 你说「就做这个」并过三问 |
| `clarify` | 回答「做成什么样算成 / 不做什么 / 谁用 / 有什么假设」 | 四类都答清，`clarify_done` 通过校验 |
| `idea` | 读一遍 IDEA.md，确认写的是你真想要的 | 你说「对，就是这个」 |
| `tech` | 看技术清单，把「必须你自己写」的项挑出来 | 清单覆盖所有活，且在预算内 |
| `decide` | 选一条路：先做小验证 / 直接开工 / 交给 AI | 你选，不是 AI 替你选 |
| `verify` | 时间盒内（≤60 分钟）验一个假设 | 出结果：通过 / 不通过 / 说不清 |
| `build` | 一张卡一张卡地做，学 → 做 → 验 | 每张卡都有证据，没有 `todo` / `stale` |
| `ship` | 断网跑一次，讲清你自己改了什么 | 三项都为真 |
| `done` | 做成了 | — |
| `handoff` | 交给 AI 做，你只验收 | — |
| `dropped` | 证伪或搁置 | 必须给理由 |

`inbox` 不会停留：立项那一刻直接跳到 `clarify`。

## 三问：立项前必须自己回答

模型会逼你答，别糊弄——这三个问题答不上来，说明还不该做。

1. **还想做吗**（现在不做会怎样）
2. **现在做吗**（不是「以后有空」）
3. **一个人做得完吗**（做不完就先砍）

## 「做成了」必须能看见

`clarify` 阶段最容易被糊弄的一条。**不合格**的写法：

- 功能都实现了
- 完成了记账功能
- 基本搞定了

**合格**的写法（能点开、能输入、能导出、能看到结果）：

- 打开网页能输入一笔 12.5 元的午餐，刷新后这笔还在
- 点导出按钮，下载到一个 Markdown 文件，里面有这周的 7 笔

不合格会被工具当场拒绝，理由里会告诉你改成什么形状。

## 卡住了怎么办：三档升级

**先自己读报错**——一半的「卡住」只是没看最后一行。

| 档位 | 什么时候用 | 你会得到 |
|---|---|---|
| 第一档 | 卡 10 分钟以内 | 一个问题，指向你自己去看某处（文档 / 报错 / 你写的那几行） |
| 第二档 | 卡超过 10 分钟 | 一个更小的步骤：把这一步拆成能立刻动手的一小步 |
| 第三档 | 卡超过 30 分钟 | 一个**不超过 10 行**的可运行骨架 + 为什么这么写 |

第三档仍然不给完整实现。骨架是脚手架，不是答案——你要在它上面接着写。

## 每张卡的形状

一张卡 = 一个能独立验收的小步骤。

- **学**：只讲这张卡需要的那一个概念，讲到你能复述
- **做**：你自己写。AI 在旁边看，写完再说下一步
- **验**：`plando_check` 跑一条已声明的命令，或者 AI 读你的代码找证据

**没有证据不算完成。**「我懂了」不是证据，命令输出和文件变化才是。

## 你会在什么时候被拦住

拦住你的通常是**守卫**，它会用这种形状回你：

```
plando：现在是「边做边学」阶段，这个模式不允许写文件——下一步：用 plando_card 推进当前任务卡。
```

看到 `plando：` 就说明是模式在管你，不是工具坏了。

两种拦法：

- **结构性**：预设里根本没挂写工具、命令工具。这不是"被拒绝"，是它们不存在。
- **守卫**：读工具照常放行（AI 要读你的代码才能验收），写 / 命令 / 子代理一律拒绝。

唯一能写文件的是 `plando_scaffold`，它只写 7 个白名单配置文件（`package.json`、`tsconfig.json`、
`.gitignore`、`.env.example`、`pyproject.toml`、`requirements.txt`、`Cargo.toml`），而且必须对应
TECH 清单里**归属=ai** 的项，内容还要过校验：`postinstall` 这类会自动执行的钩子一律拒，`scripts` 的值要是有白名单的命令（`&&` 串联、环境变量前缀、`tar` / `bash` 这类一律不行）。
你的源码它碰不到。

## 自动提交默认关着

`autoCommit: false` 是默认值。也就是说：模式产物（IDEA.md / TECH.md / `.plando/`）**不会**自动进 git。

想开的话，在 profile 的 `cordis.patch.yml` 里覆盖本插件的配置：

```yaml
- id: plan-do-mode
  config:
    autoCommit: true
```

开启后它也只 `git add --` 那 5 类产物，**绝不 `git add -A`**，你正在写的代码不会被卷进提交。

## 预算：为什么要限制你

默认 `{ mustUnderstand: 5, totalMinutes: 600 }`——最多 5 件事必须你亲手写，总量 600 分钟。

这不是怕你累，是**防止项目大到学不完**。超了工具会拒绝并告诉你超了多少、怎么降级：

```
plando：技术清单超出预算，「必须自己写」有 7 条，超出上限 5 条 2 条，请把 2 条降级成 follow 或 ai……
```

降级不是失败。把「必须自己写」降成「AI 写、你读懂了」是正当选择，只是要在 TECH 清单里写明。

## 三条你迟早会想违反的规则

1. **「你直接帮我写完吧，我自己看一遍」** —— 你会这么想，AI 会拒绝。看一遍不算学会。
2. **「这次先跳过验证，下次补」** —— 没有证据的卡不能标 done。补不上就降级成 `downgraded`，留痕。
3. **「状态文件我手改一下就行」** —— 手改前先备份。`schemaVersion` 改错、JSON 写坏，工具会报错**并拒绝重置**（这是故意的：宁可你手工修，也不能悄悄清空你的进度）。
